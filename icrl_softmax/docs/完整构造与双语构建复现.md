# 早期 sampled-SARSA 构造复现（历史依据）

> 历史范围：本文说明旧 sampled-SARSA 构造及其复现，保留作为已有代码的依据。当前研究状态见 [项目入口](../ACTIVE_WORKSPACE.md)。旧双语论文构建说明及对应过时稿件已移除。

本指南把三个容易混淆的层次分开：精确定理的模型假设、逐矩阵构造验证，以及用于统计评估的 control sweep。所有命令均从项目根目录 `icrl_softmax/` 运行。

## 1. 精确定理究竟覆盖什么

精确结果针对一个明确指定的固定权重、两块 residual attention--FFN 构造。对一批 transition token，令 \(X_k=(S_k,A_k)\)、\(X'_k=(S'_k,A'_k)\)，并令 \(n_x=|\{k:X_k=x\}|\)。构造实现

\[
Q^+(x)=Q(x)+\frac{\alpha}{n_x}\sum_{k:X_k=x}
\left[R_k+\gamma Q(X'_k)-Q(X_k)\right]
\]

（未访问的 pair 保持不变）。它有以下边界：

- equality-routing mask 是外部提供、随输入内容变化的结构信息；定理没有证明网络会学习或发现这个 routing。
- visited-query/null-token gate 也由外部提供，保证未访问的 Q-memory query 只读 null token，并确保每一行 softmax 都有非空 support。
- 构造没有 layer normalization 或 dropout。
- 它使用双向结构化注意力，不是 decoder-only causal Transformer。
- 单个固定构造对应固定 \(\alpha\)；变化步长需要按轮次改变输出尺度或使用对应的块族。
- 同一 pair 的 \(n_x\) 个 residual 被 softmax 均匀平均，因此系数是 \(\alpha/n_x\)，不是全批次 \(\alpha/N\)。只有 singleton batch（或每个 pair 单独一次）才与逐样本顺序 SARSA 更新直接相同；全局 \(\alpha/N\) 只有在另外施加计数条件时才可能吻合。

这里的 hard mask 是精确定理的外部 routing 算子，而不是网络自行产生的 prompt 技巧。去掉 equality mask 后的有限-logit 结果只是近似结果，并且当前版本仍保留 visited/null gate，不能写成完全 mask-free。

## 2. Literal token-matrix witness

运行：

```bash
python verify_end_to_end_sarsa.py
```

验证器不是只把最终更新式再算一遍。它建立完整 prompt

\[
H_0\in\mathbb{R}^{d\times L},\qquad
d=2m+8,\quad L=m+N+1,
\]

其中前 \(m\) 列是 Q-memory token，接着 \(N\) 列是 transition token，最后一列是 null token。脚本随后逐项执行：

1. 构造 current-pair 与 next-pair 的 selector、完整 query-by-source support mask；
2. 用显式 \(W_Q,W_K,W_V,W_O\) 和标准 \(1/\sqrt{d_k}\) 缩放的指数 softmax 完成两个检索头；
3. 用显式两隐藏单元 ReLU FFN 计算 signed residual \(\delta=R+\gamma Q(X')-Q(X)\)；
4. 用写回头对同一 current pair 的 residual 做均匀聚合，并以输出尺度 \(\alpha\) 写入 Q-memory value 行；
5. 核对所有矩阵形状、每行 support、softmax 行和、null 行为、未使用 token 坐标保持不变，以及正负 TD residual 均可通过 value 通道。

最后，literal 路径会同时与两条独立路径比较：

- compact attention 实现；
- 直接按定义计算的 sampled-SARSA reference。

默认固定测试当前输出的 literal prompt shape 为 `[32, 20]`，literal/reference 与 literal/compact 的最大绝对误差应在浮点舍入量级（当前均为 `5.551115123125783e-17`），并以

```text
PASS end-to-end softmax SARSA construction
```

结束。若未来测试尺寸变化，应以脚本内断言和 `PASS` 为主，不要把 `[32, 20]` 当作定理要求。

## 3. Control sweep 不是完整 prompt 实现

运行统计控制实验：

```bash
python evaluate_softmax_sarsa_control.py
```

这条路径直接通过数组索引读取当前值 \(Q(s,a)\) 与下一值 \(Q(s',a')\)，先在代码中形成 sampled-SARSA residual，再把分组均值交给 softmax/kernel 写回算子。这样可以高效运行多任务、多更新的 sweep，但它没有实例化完整 \(d\times L\) prompt，也没有重跑两个检索头和 residual FFN。

因此证据应这样归属：

- `verify_end_to_end_sarsa.py`：证明实现层面的完整构造见证，并与 compact/reference 对照。
- `evaluate_softmax_sarsa_control.py`：验证直接索引设定下写回核的数值行为和闭环控制表现。

后者不能单独声称“完整 Transformer prompt 在大规模任务上端到端运行”。
