## 研究问题

在 FP-CERTFIX-001 修正协议（前 n 固定计数、每步新批次、MP 证书）下，把冻结 horizon 从 12 延长到 **32**：

1. 实际注意力网络与 numpy 参考路线的逐步判决（发出/弃权、η 选择）在哪一步开始出现分歧（如果会）？**只实测，不外推。**
2. 网络估计差是否随步数增长？
3. 尾部判决（margin 小时）是否有任何一个是算术支配的——用与 FP-CERTCHECK-001 相同的 float64/fsum/mpmath-50 三层重算。

本任务**不**预设失效步数（旧的"第 17 步"说法已撤回）；也不声明超过 32 步的任何性质。

## 预登记（运行前冻结）

- 协议：n=16,384/对/步，每步新批次（FP-CERTFIX 种子计划），K=32，`δ_k = 0.05/32`，两臂（mp、split），48 条记录（原 24 环境 × 2 路线），numpy 与 network 两个生产者分别运行同一协议。
- **H1**：网络与 numpy 的逐步判决分歧数按步报告；若 32 步内零分歧，结论仅为"32 步内零分歧"。
- **H2**：漂移探针（每步两生产者同策略同批次的 sup 差）报告逐最差值；若超过冻结容差 `1e-4`，报告首次超差步。
- **H3**：对 numpy 运行中全部已发出判决做 fsum 重算、对 `|margin| < 1e-6` 及弃权点做 mpmath-50 重算；报告首个翻转步（若有），否则声明"32 步内无算术支配判决"。
- 描述量（非假设）：各阈值（1e-4/1e-6/1e-9）被 margin 首次穿过的步数。

## 验收标准

1. 两生产者的逐步分歧表（含 0 的可能）；漂移逐步表。
2. 高精度核查覆盖全部已发出判决与全部弃权点；任何翻转如实报告并收缩可信步数。
3. 所有失败/弃权保留。

## 停止条件

- 出现首个判决翻转 → 停止，报告受影响范围，不外推。
- 网络漂移超容差 → 停止网络路线更远步数的主张，报告首超步。
