# 共享输入生成器的只读检查（FP-COMPOSE-001 / Claude）

- 依据：任务单 §8 —— 「共同输入生成器仍是共享依赖，**必须单独只读检查其抽样法则/首访前提并记录限制，不称完全独立发现**」。
- 性质：**只读检查**。不修改任何生成器，不写入封存包，不改变任何判决。
- 对象（四个共享依赖）：
  `mdps.sample_mdp` → `evaluate_fixed_policy_q_routes.make_mdp` / `make_policy` →
  `evaluate_fp_xfam_001.build_family_task` / `training_batch` / `vectorised_batch_generic` →
  `fp_certfix_first_n.first_visit_batch`。
- 程序：`check_shared_generators.py`；输出 `results/FP-COMPOSE-001/claude/verification/shared_generator_check_{f1,f2}.json`
  （f1 = mixing 0.5 / task 200；f2 = mixing 0.7 / task 300；32,768 链 × 32 项）。
- 结论：**这些生成器的输出与其声称的抽样法则一致；但它们是两条路线共用的依赖，本检查不使两条路线变得独立，也不构成对受测对象的独立发现。**

## 1. 抽样法则（代码事实）

| 环节 | 法则 | 关键代码事实 |
|---|---|---|
| `sample_mdp` | `P ~ Dirichlet(1,…,1)` 逐 (s,a)；`R ~ U(-1,1)` 逐 (s,a,s')；`p0 ~ Dirichlet(1,…,1)` | **三者都 `astype(np.float32)`** |
| `make_mdp` | `P ← (1−mixing)·sticky + mixing·P_rand`，其中 `sticky[s,a,s]=1`；`R[:,0,:] += gap_bonus` | 在 float64 中做；`P_rand` 先按行归一化 |
| `make_policy` | 每行 `pi_min=0.15`，每状态随机一个优选动作取 `1−(A−1)·pi_min` | 行和为 1，严格正 |
| `build_family_task` | `rng = default_rng([SEED, round(100·mixing), task_index])`，按 **MDP → policy** 顺序消费该 rng，并把**同一个已推进的 rng 交回** | 训练批与 MDP/policy 抽样**共享一条随机流且有顺序依赖** |
| `training_batch` | 从 `mu_state` 抽**一个**起始状态，跑**一条**长度 65,536 的轨迹 | 见 §3 限制：**串行相关**，非 iid |
| `vectorised_batch_generic` | 每次调用 `default_rng(seed_parts)`，`seed_parts=[SEED,SALT,round(100·mixing),task_index,step]`；起点 `~mu_state`，动作 `~policy_c(current)`，后继 `~(u > cumsum(P[current,chosen]))` | **按 step 索引的独立随机流**；动作/后继用 `>` 反演抽样，末类由 `clip` 兜底 |
| `first_visit_batch` | 每条链对每对 `(s,a)` 只保留**首访**那一条；`counts[x]` = 访问过 x 的**不同链数** | 保留位置按链序排序 |

**两处容易误读、值得记下的事实**：

1. **训练批用的是 `mu_state`，不是 `mdp["p0"]`。** `p0` 被 `sample_mdp` 抽出但**从未被本协议使用**（`training_batch` 与 `vectorised_batch_generic` 都接收 `mu_state` 参数）。
2. **`mu_state` 是行为策略链的平稳分布**（`policy_quantities` 里的 `stationary_distribution(p_pi)`）。因此链的起点不是状态上的均匀分布，**每对的首访容量继承了这个集中度**——这也是本任务实测最小对容量仍有 4,317 的原因。

## 2. 经验核对（把输出与解析律对照，而不只是读代码）

蒙特卡洛地板：对离散律、`n` 个样本、`k` 个原子，TV 的量级约为 `½·Σ_i sqrt(2·p_i(1−p_i)/(π·n))`。下表把它与实测并排，**避免把噪声当成偏差**。

| 检查 | f1 | f2 | 地板/判读 |
|---|---|---|---|
| `P` 行和偏离 1 的最大值 | `1.11e-16` | `1.11e-16` | 可忽略；`clip` 兜底不会造成可见畸变 |
| 起点分布 vs `mu_state`（TV） | `0.00395` | `0.00363` | 地板 ≈ `0.0045`（n=32768）→ **在地板内** |
| 动作律 vs 行为策略（最大绝对偏差） | `0.00255` | `0.00125` | 每状态样本 13.1 万–28.9 万 → 在地板内 |
| 转移律 vs `P`（最大绝对偏差） | `0.00774` | `0.00671` | 216（f1）/ 144（f2）个格取最大值；单格 sd ≈ `0.0066`，**与"取 216 次的最大值"相符** |
| 奖励 = `R[s,a,s']`（逐元素） | **true** | **true** | 奖励对三元组确定 |
| 同种子逐位可复现 | **true** | **true** | 换 step 则不同 |
| 首访计数 = 我另写的实现 | **true** | **true** | 独立重实现（lexsort 分组）与参考实现（逐对掩码）**完全一致** |
| 首访保留位置 = 我另写的实现 | **true** | **true** | 同上 |

### 2.1 首访律（本检查最实质的一项）

首访残差 `Y = R[s,a,s'] + γ·(π(s')·Q̂(s')) − Q̂(s,a)` 只是**首访那一次转移** `(s,a)→s'` 的**确定性函数**。因为 MDP 有限，`Y` 最多取 `S` 个值，其**精确律**就是把 `P[s,a,:]` 的质点推过这个映射。于是"首访给出的是 `P_x` 的一次新鲜抽样"这一操作性内容**可以直接逐对核对**：

| | f1 | f2 |
|---|---|---|
| 核对的 (s,a) 对数 | 24 | 12 |
| 最小保留样本数 | 13,108 | 17,421 |
| TV **中位** | `0.00492` | `0.00416` |
| TV **最差** | `0.00931` | `0.00694` |
| 地板（按最小 n 与 S 个原子） | `0.00779` | `0.00522` |
| 判读 | 中位**低于**地板，最差 ≈ `1.2×` 地板 | 中位低于地板，最差 ≈ `1.3×` 地板 |

**判读：与"首访样本服从 `P_x`"一致。**

## 3. 限制（任务单 §8 要求记录，逐条）

1. **这是共享依赖，不是独立重实现。** 本检查**不**使两条路线变得独立，**不得**被写成"对受测对象的独立发现"。它检查的是**输入生成器**，不是被判定的组合本身。
2. **环境本身带有 float32 的信息量。** `sample_mdp` 把 `P`/`R`/`p0` 抽成 float32；`make_mdp` 随后在 float64 中归一化、混合、给动作 0 加 `gap_bonus`。实测：`P` 存储值**不是** float32 可精确表示的（混合所致），`R` 只有**动作 0 不是**（加了 `gap_bonus`），**动作 1..A−1 仍是**。故本任务的一切陈述都是关于**这个存储下来的 MDP**，不是关于某个理想实数 MDP。
3. **起点不是状态上的均匀分布**，而是行为链的平稳分布 `mu_state`；每对首访容量因此不均匀（实测最小 4,317 / 中位 10,014）。弃权阈值 `min_visits=2000` 是这条集中度之下的安全边界。
4. **训练批是一条串行相关的轨迹**（长度 65,536，单一 `mu_state` 起点），**不是 iid 样本**。这**不破坏**认证：`L12` 的浓度步作用在**认证批**上，并把 `Q̂` 当作**任意固定**的历史可测函数。但它意味着**生产者 `Q̂` 不是任何量的 iid 估计**，不应被当作估计量来讨论其方差。
5. **`training_batch` 与认证批共用 `build_family_task` 的 rng 顺序**：训练批的抽取依赖 MDP/policy 抽样**之后**的 rng 状态，所以任何重放都必须按 `build_family_task → policy_quantities → training_batch` 的**同一顺序**消费 rng（本项目此前已因此出过一次 `KeyError`）。认证批则**不受影响**：它用**另起的** `default_rng(seed_parts)`。
6. **首访律只核对了边缘律，未核对"给定容量 n 时集合内的独立性"。** 后者来自**各链独立生成**这一结构事实，不是本模拟能建立的；本程序**不**声称证明了引理 A'。

## 4. 我自己的一个被否定的探针（记录在案）

本节第一版的首访探针问的是：*在访问某对的链中，只访问一次的链与访问多次的链，其首访残差是否相同？* 结果给出 **最差 `|z| = 49`**。

**该探针问错了事件，结论无效。** 一条链**是否会再次**访问 `(s,a)`，取决于与 `Y` **同一个**首访后继 `s'` 之后的路径；因此两者不独立是**预期之内**的，与引理 A' 不矛盾。引理 A' 的条件事件是「**哪些**链访问了 x」，**不是**「每条链访问了**几次**」。已改用 §2.1 的精确律核对，并把这段错误留在 `check_shared_generators.py` 的输出里（`rejected_first_probe` 字段），不静默删掉。

**这与本项目反复出现的同一个教训一致**：一个显著的数字（`z=49`）既可能指向真问题，也可能指向**问错的题**；区分二者的办法是把"要检验的命题"写成可核对的形式，而不是看哪个数字大。

## 5. 判定

- **抽样法则**：`sample_mdp` / `make_mdp` / `make_policy` / `build_family_task` / `training_batch` / `vectorised_batch_generic` 的输出**与其声称的法则一致**（起点、动作、转移、奖励四项各自在地板内），**且逐位可复现**。
- **首访前提**：首访保留的**机制**（每条链每对一个首访、计数=访问链数）由**独立重实现**逐位确认；首访值的**边缘律**与 `P_x` 的精确离散律一致。**给定容量的集合内独立性未由本检查建立**。
- **本检查不改变任何判决**，也**不提高** FP-COMPOSE-001 的证据等级：它审计的是两条路线**共用**的输入侧，而不是被判定的组合。独立验证的缺口（无第二作者）**依然存在**。
