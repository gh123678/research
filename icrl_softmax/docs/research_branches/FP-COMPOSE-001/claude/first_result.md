D1 记录允许看到“按状态规则”在接缝处实际做了什么。**所有 1536 个步骤都至少更新了一行**，但**并非所有行每步都更新**：

| 选中 eta | 行数 | 占比 |

**这说明接缝的性质**：如果改用合取（全行）规则，只要有 1038 行中的任意一行不通过，**整格**就会在该步停止；按状态规则则让这些行原样不动、其余行继续更新。13.5% 的状态-行在整个 K=4 内从未满足 `LB_s>0`，而每一格、每一步仍然发出了至少一行的更新。

## 6. 已知缺陷、边界与不主张

### 6.1 已发现的实现缺陷（均已修复，记录在案）

1. **`analyze.py` 的路线合并缺陷（分析层，非实验层）**：`cells_of()` 用“生产者名”作键展开格，导致同一环境实例下第二条路线（`expected_finite`）**覆盖**第一条（`expected_exact`）。症状是两组路线均值在 12 位小数上完全相同。修复后 `expected_exact` 才真正被审计，`min value delta` 从 0.004015 修正为 **0.002863**（正是 exact 路线的更小值），总体闭合率从 [0.3404,0.5974,0.7436,0.8144] 修正为 **[0.3394,0.5964,0.7431,0.8147]**。**封存的 `task_results.json` 不受影响**（两条路线的数据都正确落盘），修复后 `analyze.json` 的分组均值与独立重算逐位一致。H1/H2/H3 判定不受影响。
2. **D2 墙钟归类**：初版把 network 格的同策略额外 numpy 审计计入“生产者墙钟”，违反 §9“额外同策略 numpy 审计成本单列”。已拆分为 `audit_recompute`。
3. **§3 清单缺项**：初版清单缺任务单 SHA256、全部调用代码 SHA256、线程数、执行命令与起止时间。已补入 `run_metadata`。
4. **§7 守卫缺失**：初版在检测到 H1 疑似异常时只记录不中止。已实现“发现即写出 `h1_anomaly.json` + 部分结果并立即终止全部正式采样”。本次运行未触发。

### 6.2 §6 高精度诊断程序的状态

`diagnose_boundary.py` 按 §6 实现：对指定 (族, mixing, task_index, route, producer, step) 用 **80 位与 120 位十进制精度**重算逐对残差均值/ddof=1 方差、L12 半径、eps、E_Q、逐行 LB 与选中 eta、`pi_before`/`pi_after` 的 Q^π 与 v^π、实际 sup 误差、价值增量，并给出两精度之间的一致性差。

**本次运行没有触发条件，所以该程序未被用于任何“放行”判断**。它在无异常步骤上跑通以确认可用。**必须保留的限制**：两个精度一致是强数值一致性检查，**不是形式区间证明**，不能把结果升级为已验证定理——这一点写在程序输出与 `analysis.json` 的 `note` 中。

### 6.3 明确不主张

- 不主张一般等成本优势；不主张后段收益或几何收敛（K=4 不足以支持，本任务也不检验）。
- 不主张任何跨精度、跨种子或跨机器的稳定性；不主张误差不随维度增长。
- 不主张网络能自我认证：网络只产生 Q̂，认证由**外部** L12 完成，网络不读认证批。
- 不主张整个实验矩阵的联合 95% 保证：风险是**单条生产者-路线轨迹**级（delta_total=0.05），**不**覆盖 192 条记录或两生产者的联合事件。
- 不主张 L12M/L12S/L123 或任何传播构造有效或无效——本任务**未使用**任何传播构造，对它们不发一言。
- 不主张浮点形式化保证：概率论证支持理想实数协议；Q̂ 的已输出浮点值作为确定输入处理。
- 不主张本轮是泛化发现：复用已测环境，明确标为**确认性组合验证**。
- **本轮结果在对方路线验证完成前一律为“初步结果”。**
