# 门限余量（headroom）分析：界从哪里来、为什么要松掉（FP-COMPOSE-001 / Claude）

- 程序：`analyze_headroom.py` + `quantify_range_looseness.py`
- 输出：`results/FP-COMPOSE-001/claude/verification/headroom_analysis.json`
- 性质：**只用封存包的只读分析**。不开新协议、不加实验臂、**不改任何冻结量**。回答的是对抗性检验留下的那个问题：
  `y_range` 随步增长，这条接缝离"没有任何行满足 `LB_s>0`"的停点还有多远？

---

## 1. 门限是精确可算的，不需要抽样

对一行 `s` 与一个 `η`：

```text
LB_s(η) = ⟨Δπ_s(η), Q̂_s⟩ − E_Q·‖Δπ_s(η)‖₁
```

该行被更新 ⟺ 存在 `η` 使 `LB_s > 0` ⟺

```text
E_Q < h_s := max_η  ⟨Δπ_s(η), Q̂_s⟩ / ‖Δπ_s(η)‖₁
```

于是该格发出 ⟺ `E_Q < h := max_s h_s`。**`h` 是精确门限**：它是封存的 `(π_before, Q̂)` 的**确定性函数**，
不含任何概率或抽样。`h/E_Q` 就是"认证误差还能再涨多少倍，这一格才会哑掉"，`E_Q* = h` 是临界值。

## 2. 余量在收窄，而且有一格已经很紧

`h/E_Q` 的中位数（每族 768 个格-步）：

| 族 | 步 1 | 步 2 | 步 3 | 步 4 | 4 步合计 |
|---|---|---|---|---|---|
| f1 | 2.805 | 2.735 | 2.339 | **1.990** | ×0.709 |
| f2 | 4.387 | 3.571 | 3.407 | **3.015** | ×0.687 |

即**每步约 −9%**。**全部 1536 个格-步里最紧的一格**是
f1 / mixing 0.5 / task 207 / expected_exact / network / step 4：`h = 0.2775`，`E_Q = 0.2551`，
**`h/E_Q = 1.0876`** —— 只剩 **8.8%** 余量。

同时每步"高于 `E_Q` 的行数"中位数从 `5/6` 降到 `4/6`（f1），f2 是 `4/4` 保持不变。
所以"K=4 全部发出"是真的，但**它不是在余量充裕的情况下发生的**。

## 3. 为什么会收窄：**不是因为问题变难，而是因为冻结公式松**

`E_Q` 只涨了 ×1.056（f1）/ ×1.174（f2），而 `y_range` 涨了 ×1.426 / ×1.513。原因在 `y_range` 的**具体形式**。

冻结任务单 §3 规定 `y_range = 2(R* + γ‖V̂‖∞ + ‖Q̂‖∞)`。而本项目**自己的单侧证明文档**
（`docs/derivations/FP-L12-one-sided-proof.md` §4）推导的是**另一个、更紧的**界：

```text
range(Y_x) ≤ 2R* + γ·span(V̂) ≤ 2R*/(1−γ)        F1: 10     F2: 13.33
```

`span(V̂) = max V̂ − min V̂`。两者都是 `(Q̂, π)` 的确定性函数，**都是 `H_{k-1}` 可测的**，
所以用哪一个都**不涉及** `L12M` 那类"把当前数据的函数代入固定函数不等式"的误用。

**实测差距（1536 个格-步）**：

| 量 | f1（R*=1.5） | f2（R*=2.0） |
|---|---|---|
| `Y` 的**精确值域**（从存储 MDP 枚举）最大 | `5.167` | `5.096` |
| 紧界 `2R* + γ·span(V̂)` 中位 / 最大 | `4.095` / `6.233` | `5.078` / `7.160` |
| 证明文档终界 `2R*/(1−γ)` | `10.000` | `13.333` |
| **冻结公式 `y_range`** 中位 / 最大 | `10.261` / **`18.307`** | `15.707` / **`23.571`** |
| **松度 `y_range / 紧界`** 中位 / 最大 | **`2.46×`** / `3.58×` | **`3.10×`** / `4.58×` |
| 松度随步（1→4） | `1.99 → 2.86` | `2.48 → 3.38` |

**零违规**：精确值域在每一个格-步上都满足证明文档的界（`0` 次违反），也满足紧界（`0` 次违反）。
所以**证明文档的 `Y_RANGE=20` 论证没有被本数据推翻**——它界的是 `range(Y)`（实测 ≤ `5.17`），
与代码里那个名字相近的 `y_range`（实测到 `23.57`）**是两个不同的量**。

**而 `y_range` 在 148/1536 步（9.64%）超过 20，全部在 f2**，最大 `23.57`；相应地 `E_eff = y_range/2` 最大 `11.79 > ENVELOPE=10`。
这**不构成不健全**（`y_range` 是 `2·sup|Y|` 的合法上界，对抗性检验 ② 已精确确认），
但它说明：**常数 `Y_RANGE=20` 与代码里每步计算的 `y_range` 同名而不同物**，
一个满足 `range(Y) ≤ 2R*/(1−γ) < 20` 的实例，其代码量可以到 `23.57`。**这是一个命名与量纲的混淆风险，应当显式记录。**

## 4. 松度值多少：`y_range` 项占了半径的多大一块

在 `eps` 取到 `max` 的那一对上（`E_Q` 正是由它决定）：

| 量 | 中位 |
|---|---|
| Bernstein 项 `sqrt(2·var·log/n)` | `0.02494` |
| `y_range` 项 `(7/3)·y_range·log/(n−1)` | `0.02125` |
| **`y_range` 项占半径的比例** | **`46.3%`** |
| `y_range` 项 > Bernstein 项的步占比 | `39.2%` |

（注：若在所有对上取中位，`y_range` 项在 `92.5%` 的对上更大；但决定 `E_Q` 的是 `argmax` 那一对，
故上表用 `argmax` 对的口径。两个口径不矛盾，含义不同。）

于是把 `y_range` 换成紧界的**算术后果**是：半径约乘 `0.54 + 0.46/2.7 ≈ 0.71`，
即**半径约小 29%，`E_Q` 约小 29%，余量比 `h/E_Q` 约大 1.4 倍**。
这解释了余量为什么收窄：**`y_range` 项随 `‖V̂‖∞` 线性增长（×1.45），而 `Y` 的真实值域一直只有约 5**——
**收窄主要来自冻结公式的松度，不是来自问题本身变难。**

## 5. 我**没有**做什么（边界）

- **没有**跑任何反事实臂。§2 明令"不加入额外实验臂"，所以本节只报告**两个界的代数比值**，
  **不报告**"换成紧界会多发多少步/多更新多少行"——那需要新的判决流程，属于新任务单。
- **没有**修改任何冻结量。§3 冻结的就是 `y_range = 2(R*+γ‖V̂‖∞+‖Q̂‖∞)`，实现**完全符合冻结定义**；
  松度是**冻结公式自身**的性质，不是实现错误。
- **没有**推翻 `FP-RANGE-001`。它的对象是 `data_range` 这一数据驱动上界在**冻结 `π₀` 第 1 步**的表现，
  与本文的"逐对精确值域 vs 冻结公式"不是同一个问题。
- 加密的 `K>4` 外推**只是外推**：`h` 与 `E_Q` 都是策略轨迹的非线性函数，
  按 −9%/步外推，f1 中位约在第 12 步附近触到 `h/E_Q = 1`、f2 约在第 16 步，而最紧那一格约再 1 步。
  **这是从 4 个点、单一协议做的对数线性外推，不是测量**，且不能排除趋势本身改变方向。

## 6. 可以据此刻画的接缝边界（有限、可复核）

> 在 FP-COMPOSE-001 冻住的协议下，这条接缝在 `K=4` 内**每一步都仍有余量**（最紧 `h/E_Q = 1.088`），
> 但余量以约 **−9%/步** 收窄；收窄的**主要来源是冻结 `y_range` 公式相对 `Y` 真实值域的 2.5–3.1 倍松度**
> （该松度随步增长到 3.4–4.6 倍），而**不是**认证误差本身的快速增长（`E_Q` 4 步只涨 ×1.06–1.17）。

**这条边界比"K=4 全部发出"信息量大得多**：它说明了失效会以什么方式、由什么项驱动地到来，
并给出一条**可预登记的预测**（§5 末），供未来任何 `K>4` 的任务去检验——而不是我现在去跑它。
